{\large\bfseries\color{reportnavy} Abstract\par}
\texttt{episynth} is a Python library for comparing probabilistic forecasters
trained on synthetic time series. A run configuration specifies the generator,
forecast window, model, and training budget. The library records the evidence
needed to compute prequential excess loss, requential coding costs, and
predictive $\mathcal V$-information. It also provides a Bayesian likelihood
reference for a known process. Across eleven generators, all three measures
had weak rank associations with GIFT-Eval CRPS at their reported budgets.

\section{Scope}\label{sec:scope}
Prequential excess loss estimates the loss accumulated during learning relative
to the trained predictor's loss rate~\cite{finzi2026}. Predictive
$\mathcal V$-information quantifies the improvement available from the
forecast context~\cite{xu2020}. Downstream evaluation scores trained
predictors on external forecasting tasks. The
\href{https://github.com/intsystems/Epiplexity/tree/main/publications/article}{companion article}
develops the statistical interpretation of the generator comparison.

\section{Data and predictive model}\label{sec:data}
\subsection{Series and forecast windows}
For a fixed generator and length $L$, \texttt{Generator.generate} maps
$B$ seeds to a $B\times L$ array of univariate series. The same seed
specifies the same series independently of the batch. A \texttt{Corpus}
retrieves precomputed series by seed, and a \texttt{Mixture} maps each seed
to a component and a component seed. Both use the same interface as an
online generator. \repolink{src/episynth/generators/base.py}{Generator interface.}

\texttt{WindowSpec} defines the series length, the distribution over context
lengths $c$, and the forecast horizon $h$. The horizon is the number of
observations to predict immediately after the context.
Given a series $x_{1:L}$,
\texttt{make\_windows} uses the seed to draw $c$ and a valid start index
$r\in\{1,\ldots,L-c-h+1\}$. The context and forecast target are
\begin{equation}
 C=x_{r:r+c-1}, \qquad Y=x_{r+c:r+c+h-1}.
\end{equation}
Optional uniform dequantization also uses the series seed.
\texttt{WindowStream} preserves window identity and ordering at different
batch sizes and worker counts. \repolink{src/episynth/windows.py}{Window construction.}

\subsection{Model inputs and predictive density}
The library implements a univariate forecasting configuration of
Moirai~\cite{woo2024}. For patch size $P$ and maximum context length $c_{\max}$,
a batch occupies a tensor of shape $B\times T\times P$ with
$T=(c_{\max}+h)/P$. Contexts shorter than $c_{\max}$ are left-padded.
The observed-value mask excludes padding. The prediction mask identifies the
horizon patches and replaces their input embeddings with mask embeddings.
The target values at those positions enter the loss.

In prequential runs, the context supplies the location $\mu_C$ and scale
$\sigma_C$ for normalization. The density at each
forecast step is a mixture of Student-$t$, Gaussian with fixed standard
deviation, and log-normal densities in normalized coordinates. If $f_t$ is
this mixture density, the joint conditional density in series units is
\begin{equation}
 q(Y\mid C)=\prod_{t=1}^{h}
 \frac{1}{\sigma_C}\, f_t\!\left(\frac{Y_t-\mu_C}{\sigma_C}\,\middle|\,C\right).
 \label{eq:model-density}
\end{equation}
The likelihood evaluator and sampler apply the same change of coordinates.
\repolink{src/episynth/model/moirai.py}{Model source.}

\section{Training and run artifacts}\label{sec:run}
The training CLI validates the run configuration and selects the estimator
using \texttt{estimator}. It passes the model, generator, window specification,
training settings, and output directory. The key \texttt{estimator\_config}
supplies constructor arguments. \repolink{src/episynth/train.py}{Training CLI.}

\subsection{Batch updates and checkpoint evaluation}
Let $\mathcal B_k$ be the batch for optimizer step $k$. Before updating the
model, \texttt{Trainer} computes the window negative log-likelihood (NLL)
$\ell_i=-\ln q_{k-1}(Y_i\mid C_i)$ for each $i\in\mathcal B_k$. The optimizer
uses the average over forecast points, $(Bh)^{-1}\sum_{i\in\mathcal B_k}\ell_i$.
After the update the trainer advances the exponential moving average (EMA)
of the weights and writes the pre-update losses in window order.

\begin{figure}[H]
\centering
\includegraphics[width=\linewidth]{figures/execution.pdf}
\caption{Losses used in the prequential estimate. Training batches are scored
before their updates. The final EMA checkpoint is evaluated on separate
held-out windows, and the mean is scaled to $N$ training windows.}
\label{fig:execution}
\end{figure}

At each checkpoint, raw and EMA predictors are scored on the same held-out
windows at training precision and any separately configured evaluation
precision. A restart in the same directory restores the model, EMA, optimizer,
and batch position from \texttt{last.pt}, then resumes the seed sequence.
\repolink{src/episynth/training.py}{Trainer implementation.}

\section{Measurement methods}\label{sec:methods}
\subsection{Prequential coding}\label{sec:prequential}
Let $\bar\ell_f$ be the mean NLL per window of the final raw or EMA predictor
on held-out windows generated from the same source. Given $N$ training windows,
the estimator reports
\begin{equation}
 L=\frac{\sum_{i=1}^{N}\ell_i}{\ln 2},\qquad
 H=\frac{N\bar\ell_f}{\ln 2},\qquad
 S=L-H .
 \label{eq:area}
\end{equation}
The fields \path{total_bits}, \path{data_part_bits}, and \path{model_part_bits}
correspond to $L$, $H$, and $S$. The sign of $S$ is retained. The area in nats is
$A_N=S\ln 2$. It depends on the training procedure, the budget, and the final
weight variant. A lossless binary representation at a declared precision
would use probability masses for the quantized values and an entropy coding
algorithm to encode and recover those values.
\repolink{src/episynth/estimators/prequential.py}{Prequential estimator.}

\subsection{Predictive \texorpdfstring{$\mathcal V$}{V}-information}\label{sec:pvi}
The estimator fits a context-free predictor and a predictor with access to
context, using the same initialization, training windows, and normalization
estimated from the training targets. The context-free predictor removes
both context values and context metadata. The validation procedure selects
the best context-free checkpoint and includes it among the candidates for
the context-conditioned role. Training, validation, and test seed ranges
are checked for overlap and source coverage.

Let $d_j=(\ell_{\varnothing,j}-\ell_{C,j})/\ln 2$ on test window $j$,
where both NLLs score the same target. The estimator reports
\begin{equation}
 \widehat I_{\mathcal V}=\frac{1}{M}\sum_{j=1}^M d_j,\qquad
 \widehat{\mathrm{SE}}=\frac{\operatorname{sd}(d_1,\ldots,d_M)}{\sqrt{M}},
 \label{eq:pvi}
\end{equation}
in bits per window, together with each predictor's mean test loss.
The standard error is conditional on the selected fits. The test estimate
can be negative. The manifest \path{v_information.json} records the fitted
checkpoints, splits, and artifact paths.
\repolink{src/episynth/estimators/v_information.py}{V-information estimator.}

\subsection{OU Bayes reference}\label{sec:ou}
The Ornstein--Uhlenbeck (OU) generator is a stationary Gaussian AR(1) model
with a known prior over the autoregressive coefficient. Quadrature gives
the marginal likelihood $M(x)$ of a segment $x$. The joint reference is
$M(C,Y)/M(C)$. The pointwise reference $\prod_t p(Y_t\mid C)$ uses the
factorization in Eq.~\eqref{eq:model-density}.

The joint reference attains lower mean NLL (Table~\ref{tab:example-results}).
Both references use the same conditional marginals, so the gap estimates
the log-loss penalty for omitting dependence among future observations
given the context. The score changes under quadrature refinement are much
smaller than the gap.
\repolink{src/episynth/checks/ou_bayes.py}{Bayesian likelihood functions.}

\subsection{Requential coding}\label{sec:requential}
Requential coding reconstructs a student from updates on teacher-generated
targets~\cite{qiu2026}. The \texttt{requential} estimator uses one horizon per
message and updates once per batch. Direct mode samples from the EMA teacher
and records the sum of teacher--student log ratios in bits and a separate
plug-in overhead estimate. Finite ordered random coding (\texttt{orc}) also
writes packed indices for decoder replay. Both modes record split seeds,
message counts, and final losses.
\testlink{requential}{Codec tests.}
\repolink{doc/source/measurements.rst}{Measurement guide.}

\section{Archived pretraining and transfer}\label{sec:transfer}
We trained six-layer Moirai models (width 384, patch size 32, 10,746,600
parameters) on eleven generators for 1,953 or 39,062 updates of 1,024 windows.
Each 1,024-point series supplies a window with 13 to 512 context observations
and a 64-point forecast target. Final EMA models were scored on 100,000 fresh
windows per run. Waveform has a second initialization at 40M windows.

\subsection{Zero-shot forecast evaluation}
The original final EMA predictors were evaluated zero-shot on 55 short-term
GIFT-Eval configurations~\cite{aksu2024}. CRPS uses forecast samples and MASE
uses the sample median. Scores are scaled by the historical seasonal error,
averaged within each configuration, and compared with the seasonal na\"ive
forecast. We aggregate configuration ratios by geometric mean.

\begin{figure}[H]
\centering
\includegraphics[width=.86\linewidth]{../article/figures/transfer_results.pdf}

A ratio below one indicates lower CRPS than the seasonal na\"ive forecast.
The open marker shows the additional Waveform initialization.}

\subsection{Requential coding and \texorpdfstring{$\mathcal V$}{V}-information}
The follow-up runs use the same generator, real-window budget, and
initialization as the archived comparisons. The CRPS scores are from the
original pretrained predictors. Requential KL ranges from 8.65 to 13.49
million bits per student at 2M windows. The comparison uses the KL sum
from direct teacher draws. For $\mathcal V$-information, separate Moirai
fits with and without context are scored on 100,000 paired test windows
per run. Those results cover both budgets and the Waveform repeat.

\section{Extending the library}\label{sec:extensions}
\lstset{basicstyle=\footnotesize\ttfamily,aboveskip=5pt,belowskip=5pt}
\subsection{Register a generator}
Subclass \texttt{Generator}, set its \texttt{name}, and implement
\texttt{\_batch(seeds)}. Return one row of length \texttt{self.length} for
each seed. The example generates a sinusoid with an independent phase
for each seed.
\begin{lstlisting}[language=Python]
import numpy as np
from episynth.generators import Generator

class RandomPhaseSine(Generator):
    name = "random_phase_sine"

    def _batch(self, seeds):
        phases = np.array([
            np.random.default_rng(int(seed)).uniform(0, 2 * np.pi)
            for seed in seeds
        ])
        time = 2 * np.pi * np.arange(self.length) / 24
        return np.sin(phases[:, None] + time[None, :])
\end{lstlisting}
Import the class in \path{src/episynth/generators/__init__.py}, add it to
\texttt{GENERATORS}, and set \texttt{data.generator} to
\texttt{random\_phase\_sine} for the CLI. An estimator can also receive the
generator instance directly.
\repolink{src/episynth/generators/__init__.py}{Generator registry.}

\subsection{Register an estimator}
Implement \texttt{run(model, generator, spec, config, out\_dir)} and return a
JSON-compatible result with declared units. This example reuses the trainer
and reports the endpoint cost $H/N$ from Eq.~\eqref{eq:area}.
\begin{lstlisting}[language=Python]
from episynth.estimators import build, register

@register("endpoint_nll")
class EndpointNLL:
    def run(self, model, generator, spec, config, out_dir):
        result = build("prequential").run(
            model, generator, spec, config, out_dir
        )
        return {"bits_per_window": result["data_part_bits"] / result["n_windows"]}
\end{lstlisting}
Import the module before calling \texttt{build("endpoint\_nll")}.
For the CLI, import the module through the built-in registry and set
\texttt{estimator} to \texttt{endpoint\_nll}.
