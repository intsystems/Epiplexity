\begin{abstract}
We present \texttt{episynth}, a Python library for studying what forecasting
models learn from synthetic time series. It connects reproducible data
generation, probabilistic model training, information measurements, and
evaluation on real forecasting tasks. Researchers can compare data sources
under a common training setup, inspect the cost of learning to predict them,
and measure how much the observed past improves a forecast. The library
provides prequential and predictive information estimators, a Bayesian
reference for a known stochastic process, and interfaces for adding new
generators and measurements. We describe its architecture and demonstrate
the workflow with small CPU experiments.
\end{abstract}

\section{Purpose and scope}
Synthetic time series offer controlled ways to study forecasting. A researcher
can vary trends, periodicity, noise, or dynamics while holding the model and
training budget fixed. The resulting experiments ask two related questions:
what does a model learn from a data source, and how useful is that learning
on real forecasting tasks?

\texttt{episynth} supports this workflow in one library. Its generators provide
seeded series, its task layer turns series into forecasting windows, and its
estimators train models and return measurements with saved evidence. A separate
evaluation layer measures forecasting quality on GIFT-Eval~\cite{aksu2024}.
The current model is a probabilistic Moirai transformer~\cite{woo2024}.

One motivation is epiplexity: the amount of structure accessible to an observer
with a limited computational budget~\cite{finzi2026}. In practice, the library
measures properties of a specified model and training procedure. A learning
curve records the cost of acquiring predictive structure. A second measurement,
predictive $\mathcal V$-information, asks how much access to the past improves
prediction within a chosen model family~\cite{xu2020}.

This report describes the software and its use. Our companion
\href{https://github.com/intsystems/Epiplexity/tree/main/publications/article}{research article}
develops the coding interpretation and analyzes the completed synthetic
pretraining experiments. Source, configurations, and examples are available in
the \href{https://github.com/intsystems/Epiplexity}{project repository}.

\section{Architecture and execution}
The main objects follow the forecasting task (Figure~\ref{fig:architecture}).
A \texttt{Generator} maps seeds to series. \texttt{WindowSpec} specifies the
observed context and forecast horizon. \texttt{WindowStream} then produces
batches containing values, masks, and seed metadata. The same seed identifies
the same window across batching and worker choices. A stored \texttt{Corpus}
and a \texttt{Mixture} of sources follow the generator interface.

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth]{figures/architecture.pdf}
\caption{Library components and saved outputs. The estimator chooses the
measurement procedure. Shared task, training, and evaluation components
provide its inputs and evidence.}
\label{fig:architecture}
\end{figure}

The registry selects a measurement through \texttt{build(name)}. An estimator
receives the model, generator, window specification, training configuration,
and output directory. The prequential estimator delegates training to
\texttt{Trainer}. The V-information estimator coordinates two training runs,
validation-based model selection, and paired test scoring.

\texttt{Trainer} manages optimization, exponential moving averages (EMA) of
weights, checkpointing, and held-out evaluation. The Moirai density head
provides both samples and log probabilities. The continuous mixture used in
our examples contains Student-$t$, Gaussian, and log-normal components.
Context normalization uses observed values. Log probabilities include the
change-of-scale correction, preserving the original units of the series.

\begin{figure}[htbp]
\centering
\includegraphics[width=0.94\linewidth]{figures/execution.pdf}
\caption{A prequential run scores each fresh batch before updating the model.
Held-out scoring supplies the endpoint used to summarize the learning curve.}
\label{fig:execution}
\end{figure}

Figure~\ref{fig:execution} shows the order that matters for prequential
measurement. Training writes per-window losses, checkpoint losses, model
weights, and configuration files. This allows the estimator to recompute a
result from saved artifacts. The command-line interface validates the run
configuration and saves the selected estimator's output in
\texttt{estimator\_result.json}.

\paragraph{Prequential measurement.}
For $N$ windows, let $\ell_i$ be the NLL evaluated before the update on window
$i$'s batch. Let $\bar\ell_f$ be the final model's mean NLL on held-out windows.
The estimator returns
\begin{equation}
 L=\frac{\sum_i\ell_i}{\ln 2},\qquad
 H=\frac{N\bar\ell_f}{\ln 2},\qquad S=L-H.
\end{equation}
The fields are \texttt{total\_bits}, \texttt{data\_part\_bits}, and
\texttt{model\_part\_bits}, respectively. $S$ summarizes the excess loss
incurred during learning and retains its sign. Its value depends on the
training procedure and the chosen raw or EMA endpoint. Continuous densities
give an idealized coding score. A literal data code additionally specifies
the observation precision and an entropy coder.

\paragraph{Predictive information.}
The estimator fits a context-free predictor and a predictor that can use
context. It selects their checkpoints using validation data, then evaluates
both on the same untouched test windows. For $M$ test windows it returns
\begin{equation}
 \widehat I_{\mathcal V}=\frac{1}{M\ln 2}
 \sum_{j=1}^{M}(\ell_{\varnothing,j}-\ell_{C,j}).
\end{equation}
This estimates the improvement available from context under the supplied
fitting budget. The result includes both predictive losses, their difference,
and a paired standard error. Both predictors use the same fixed scaling
estimated from training data. The context-free model ignores context values
and metadata. Validation can select it as the conditional predictor as well.
The test standard error describes uncertainty for the fitted predictors.

\paragraph{Bayesian reference and requential extension.}
For the Ornstein--Uhlenbeck (OU/AR(1)) generator, quadrature over the known prior supplies
joint and pointwise predictive NLL. The pointwise version matches the current
Moirai forecast factorization. The functions live in
\path{episynth.checks.ou_bayes}. Requential coding~\cite{qiu2026} would add
student training on teacher-generated targets and accumulate KL divergence,
which measures predictive disagreement, with coding overhead.
Calling the current stub raises \texttt{NotImplementedError}.
The measurement guide specifies the intended
inputs, reproducible sampling requirements, and outputs.

\section{Application examples}
\subsection{Measure a learning curve}
The report includes a small waveform experiment with a one-layer model.
After installing the package, run these commands from the repository root:
\begin{lstlisting}
python -m episynth.train --config publications/technical_report/examples/prequential.json --out build/report_demo/prequential
\end{lstlisting}
The result contains $L$, $H$, and $S$ in bits. Figure~\ref{fig:demo} shows the
per-batch loss and held-out endpoint. The example exercises the same public
interface used for the larger experiments. Its small budget makes the
sequence of operations easy to inspect.

To recompute the measurement after training:
\begin{lstlisting}[language=Python]
from episynth.estimators.prequential import PrequentialEstimator
result = PrequentialEstimator(variant="ema").from_run_dir(
    "build/report_demo/prequential"
)
print(result["model_part_bits"])
\end{lstlisting}
This entry point reads \texttt{window\_loss.f32} and
\texttt{heldout\_ema\_1.f32}. The article's analysis script also supports the
archived batch-mean CSV exports, which suffice for the linear area calculation.

The final EMA predictor is scored on separate held-out windows.}

\subsection{Measure the value of context}
The second example trains the paired predictors and reports their gain on a
shared test set:
\begin{lstlisting}
python -m episynth.train --config experiments/demos/v_information.json --out build/report_demo/v_information
\end{lstlisting}
Inspect the gain in \path{v_information_bits_per_window} and its uncertainty
in \path{standard_error_bits_per_window}. The accompanying metadata records
the training, validation, and test seed ranges and the selected checkpoints.
A negative finite-sample gain is retained. This example demonstrates how to
compare paired predictions with uncertainty under a deliberately small budget.
In the recorded run, validation selects the context-free predictor for both
roles, giving a measured gain of zero.

The report's \texttt{reproduce.py} runs both examples, checks recomputation
from their saved losses, and evaluates the OU reference at two quadrature
resolutions. It records the outputs and environment in \texttt{data/}.
The larger application compares synthetic sources through GIFT-Eval and is
reported in the companion article.

\section{Validation and extension}
The existing test suite checks seeded generation, forecasting masks, density
calculations, training and resume behavior, estimator outputs, and evaluation
metrics. The report build records \ChecksPassed{} passed checks,
\ChecksSkipped{} skipped checks, and \ChecksFailed{} failures. Comparisons
requiring external benchmark data or published checkpoints report their
availability separately. Small examples additionally verify that the saved
losses reconstruct the returned measurements.

To add a generator, implement the seed-to-series contract and register the
class. To add an estimator, implement \texttt{run(model, generator, spec,
config, out\_dir)} and register its name. Its result should identify the
quantity, units, and artifacts needed for recomputation. Estimators can reuse
\texttt{Trainer} or coordinate several runs, as V-information does.

The current estimator signatures use the Moirai model interface. Supporting
another forecasting model requires adapting prediction, training, and
checkpoint handling to that interface. Requential coding additionally needs
reproducible sampling and probability evaluation for teacher and student.
These extension points are documented alongside the
\href{https://intsystems.github.io/Epiplexity/}{generated API reference}.

\texttt{episynth} provides a reproducible path from a controlled data source
to a measured training trajectory and downstream forecast scores. Its saved
artifacts support both small software examples and research comparisons
whose assumptions can be inspected and revised.
